# 🧰 Hardware y Justificación Técnica

> **Navegación**: [← resilence-strategy](../00-resilience/003-resilience-strategy.md) | [installation →](01.2-installation.md)

Selección y justificación de los componentes de hardware para el nodo
biomédico ligero sobre Raspberry Pi Zero 2 W.

---

## 1. 📋 Componentes Requeridos

| Componente | Especificación | Obligatorio |
|---|---|---|
| Placa | Raspberry Pi Zero 2 W | ✅ |
| Fuente de alimentación | 5 V @ 2.5 A (recomendado para margen con periféricos USB) | ✅ |
| Almacenamiento | microSD ≥ 16 GB (Clase 10 / A1, idealmente A2) | ✅ |
| Lector de tarjetas | Adaptador microSD → USB | ✅ |
| Adaptador de red USB | Ethernet USB (alternativa a Wi-Fi) | ⚪ Opcional |

---

## 2. 🧠 Justificación Técnica

### 2.1 Raspberry Pi Zero 2 W

Se selecciona por su **bajo consumo energético** y **factor de forma
compacto**, ideales para proyectos de biomedicina y despliegues de
servidores ligeros donde el espacio es crítico.

| Característica | Valor |
|---|---|
| Procesador | Broadcom BCM2710A1, quad-core 64-bit SoC (Arm Cortex-A53 @ 1GHz) |
| RAM | 512MB LPDDR2 |
| Consumo típico | ~2 W en idle, ~3.5 W bajo carga |
| Conectividad | Wi-Fi 802.11 b/g/n, Bluetooth 4.2 |
| Factor de forma | 65 × 30 mm |

### 2.2 Almacenamiento (microSD ≥ 16 GB)

Suficiente para alojar el SO y los archivos operativos del servidor
biomédico. Se recomienda **Clase 10 / A1** —idealmente **A2**— para
garantizar velocidades de lectura/escritura adecuadas.

> 🔭 **Roadmap**: se evalúa migrar a **SSD externo vía USB** en versiones
> futuras para mejorar el throughput de lectura/escritura y la vida útil
> del almacenamiento.

### 2.3 Sistema Operativo: DietPi

Frente a Raspberry Pi OS, **DietPi** ofrece:

- Distribución ligera y optimizada para dispositivos de bajo consumo.
- Menor uso de RAM y CPU en reposo.
- Amplia gama de **software preconfigurado** (servidores web, bases de
  datos, monitoreo).
- Herramientas de administración (`dietpi-software`, `dietpi-config`)
  que simplifican el mantenimiento.

### 2.4 Adaptador de Red USB (opcional)

Recomendado cuando se opera la Raspberry Pi en modo *headless* (sin
monitor), ya que permite acceso remoto estable vía **SSH** sin
depender del Wi-Fi integrado (que puede ser inestable en algunos
entornos).

# 🌐 04 — Configuración de Red y Verificación

> **Navegación**: [← provisioning](01.3-provisioning.md) | [golden-image →](01.5-golden-image.md)

Definición de la estrategia de direccionamiento IP (estática o DHCP) y
procedimiento de verificación post-instalación para confirmar que el nodo
es operativo y accesible remotamente.

> ℹ️ **Direcciones de ejemplo**: este documento usa el rango
> `192.0.2.0/24`, reservado para documentación (RFC 5737). Sustituye
> esas direcciones por las de tu red real (por ejemplo `192.168.x.x` o
> `10.x.x.x`).

---

## 1. 📍 Asignación de Dirección IP

Antes de encender la Pi por primera vez, define cómo obtendrá su IP.
Existen dos estrategias válidas; escoge **una** según el caso de uso.

| Estrategia | Ventaja principal | Ideal para |
|---|---|---|
| **A — IP Estática** | Endpoint predecible y fijo | Servidores en producción |
| **B — DHCP + reserva MAC** | Cero configuración manual | Laboratorios, despliegues rápidos |

---

## 2. 🔌 Interfaz de red (Wi-Fi o Ethernet)

Esta guía usa Wi-Fi (`wlan0`) en los ejemplos. Si usas el adaptador
Ethernet USB, la interfaz será `eth0` (o similar) y debes ajustar los
comandos. Habilita en `dietpi.txt` solo la interfaz que vayas a usar:

```ini
# Wi-Fi
AUTO_SETUP_NET_WIFI_ENABLED=1
# Ethernet
AUTO_SETUP_NET_ETHERNET_ENABLED=0
```

---

## 3. IP Estática

**Ventajas**: la dirección es predecible y fija, ideal para servicios que
deban localizarse siempre en el mismo endpoint. No depende del router.

### 3.1 Requisitos previos

| Requisito | Ejemplo |
|---|---|
| IP fuera del rango DHCP del router | `192.0.2.50` |
| Puerta de enlace (gateway) | `192.0.2.1` |
| Máscara de subred | `255.255.255.0` |
| DNS | `1.1.1.1`, `9.9.9.9` |

### 3.2 Configuración

**Archivo:** `dietpi.txt`

```ini
AUTO_SETUP_NET_USESTATIC=1
AUTO_SETUP_NET_STATIC_IP=192.0.2.50
AUTO_SETUP_NET_STATIC_MASK=255.255.255.0
AUTO_SETUP_NET_STATIC_GATEWAY=192.0.2.1
AUTO_SETUP_NET_STATIC_DNS=1.1.1.1 9.9.9.9
```

### 3.4 Verificación previa (evitar conflictos)

Antes de flashear, comprobar desde el host que la IP elegida no esté
en uso:

```bash
# 1. Ping simple (orientativo)
ping -c 3 192.0.2.50

# 2. Detección de duplicados por ARP (prueba confiable)
# Ajusta la interfaz (-I) a la de tu host: wlan0, wlp3s0, eth0, etc.
sudo arping -D -I wlan0 -c 3 192.0.2.50
echo $?
# Código 0 → nadie respondió (IP libre)
# Código 1 → otro equipo ya la usa
```

> ⚠️ **Un ping sin respuesta no garantiza que la IP esté libre**: algunos
> dispositivos ignoran ICMP. Confía en la prueba con `arping`.
> Una colisión de direcciones causa comportamiento errático en toda la red.

## 4. DHCP + Lookup en el Router

**Ventajas**: cero configuración manual, el router gestiona todo. Ideal
para laboratorios o despliegues rápidos.

### 4.1 Configuración

**Archivo:** `dietpi.txt` (valores por defecto)

```ini
# DHCP habilitado
AUTO_SETUP_NET_USESTATIC=0
```

### 4.2 Localización de la IP asignada

Tras el primer arranque, localizar la IP desde el panel del router:

1. Acceder a `http://192.0.2.1` (o la IP del gateway).
2. Iniciar sesión.
3. Buscar la sección **"Dispositivos conectados"** / **"DHCP Leases"** /
   **"Clientes"**.
4. Identificar la entrada por el hostname `DietPi`. Si hay varios
   dispositivos Raspberry Pi o el hostname no aparece, apaga la Pi y
   observa qué entrada desaparece de la lista.
5. Anotar la IP asignada.

> 💡 **Tip — DHCP Reservation**: la mayoría de routers permiten reservar
> una IP por MAC (*DHCP Reservation*). Es un punto medio ideal: la Pi
> sigue usando DHCP, pero siempre recibe la misma IP sin configuración
> manual en el dispositivo.

## 5. ✅ Verificación Post-Instalación

Tras insertar la microSD y encender la Pi, espera **1–2 minutos** — el
primer arranque de DietPi expande el filesystem y aplica la configuración.

Luego procede según la estrategia de IP elegida.

### 5.1 Conexion IP Estática

Conecta directamente a la IP declarada:

```bash
ssh dietpi@192.0.2.50
```

Si no responde:

1. Verifica conectividad básica: `ping -c 3 192.0.2.50`.
2. Si el ping falla → la Pi no arrancó o no se asoció a la red (Wi-Fi o
   Ethernet). Revisa [`06-troubleshooting.md`](../06-troubleshooting.md).
3. Si el ping funciona pero SSH no → problema con el servicio SSH o
   firewall del router.

### 5.2 Conexion DHCP

Localiza la IP asignada desde el panel del router (ver sección anterior),
o utiliza uno de estos métodos alternativos:

```bash
# 1. mDNS (solo si hay un servicio mDNS activo en la Pi)
ping dietpi.local
ssh root@dietpi.local

# 2. Escaneo de red con nmap
nmap -sn 192.0.2.0/24

# 3. ARP scan (más rápido en redes locales)
sudo arp-scan --localnet
```

> ℹ️ **mDNS**: DietPi no incluye por defecto un servicio mDNS (por
> ejemplo Avahi), así que `dietpi.local` puede no resolver en la
> primera conexión. Si falla, usa nmap o arp-scan.

Una vez identificada la IP:

```bash
ssh root@<IP_ASIGNADA>
```

---

## 6. 🔍 Verificación del Sistema (aplica a ambas opciones)

Una vez dentro por SSH, verificar el estado del nodo:

```bash
# Estado de servicios DietPi
dietpi-services status

# Confirmar hostname y OS
hostnamectl

# Confirmar IP y estado de las interfaces
# (wlan0 para Wi-Fi, eth0 o similar para Ethernet)
ip -br addr

# Confirmar conectividad a Internet
ping -c 3 1.1.1.1
```

**Salida esperada**: todos los comandos devuelven resultados sin errores.
Si es así, el nodo está operativo y accesible remotamente.

# 🌐 01.4 — Configuración de Red y Verificación

> **Navegación**: [← provisioning](01.3-provisioning.md) | [golden-image →](01.5-golden-image.md)

Definición de la estrategia de direccionamiento IP (estática o DHCP) y procedimiento de verificación post-instalación para confirmar que el nodo es operativo y accesible remotamente.

> **Direcciones de ejemplo**: este documento usa el rango `192.0.2.0/24`, reservado para documentación (RFC 5737). Esas direcciones deben sustituirse por las de la red real (por ejemplo `192.168.x.x` o `10.x.x.x`).

---

## 1. Asignación de dirección IP

Antes de encender la Pi por primera vez, se debe definir cómo obtendrá su IP. Existen dos estrategias válidas; se escoge **una** según el caso de uso.

| Estrategia | Ventaja e idoneidad |
|---|---|
| **A — IP estática** | Endpoint predecible y fijo; ideal para servidores en producción. |
| **B — DHCP + reserva MAC** | Cero configuración manual; ideal para laboratorios y despliegues rápidos. |

---

## 2. Interfaz de red (Wi-Fi o Ethernet)

Esta guía usa Wi-Fi (`wlan0`) en los ejemplos. Si se usa el adaptador Ethernet USB, la interfaz será `eth0` (o similar) y los comandos deben ajustarse. Se habilita en `dietpi.txt` solo la interfaz que se vaya a usar:

```ini
# Wi-Fi
AUTO_SETUP_NET_WIFI_ENABLED=1
# Ethernet
AUTO_SETUP_NET_ETHERNET_ENABLED=0
```

---

## 3. IP estática

**Ventajas**: la dirección es predecible y fija, ideal para servicios que deban localizarse siempre en el mismo endpoint. No depende del router.

### 3.1 Requisitos previos

| Requisito | Ejemplo |
|---|---|
| **IP fuera del rango DHCP del router** | `192.0.2.50` |
| **Puerta de enlace (*gateway*)** | `192.0.2.1` |
| **Máscara de subred** | `255.255.255.0` |
| **DNS** | `1.1.1.1`, `9.9.9.9` |

### 3.2 Configuración

**Archivo**: `dietpi.txt`

```ini
AUTO_SETUP_NET_USESTATIC=1
AUTO_SETUP_NET_STATIC_IP=192.0.2.50
AUTO_SETUP_NET_STATIC_MASK=255.255.255.0
AUTO_SETUP_NET_STATIC_GATEWAY=192.0.2.1
AUTO_SETUP_NET_STATIC_DNS=1.1.1.1 9.9.9.9
```

### 3.3 Verificación previa (evitar conflictos)

Antes de flashear, se comprueba desde el host que la IP elegida no esté en uso:

```bash
# 1. Ping simple (orientativo)
ping -c 3 192.0.2.50

# 2. Detección de duplicados por ARP (prueba confiable)
# Ajustar la interfaz (-I) a la del host: wlan0, wlp3s0, eth0, etc.
sudo arping -D -I wlan0 -c 3 192.0.2.50
echo $?
# Código 0 → nadie respondió (IP libre)
# Código 1 → otro equipo ya la usa
```

> **Nota**: un ping sin respuesta no garantiza que la IP esté libre, ya que algunos dispositivos ignoran ICMP. Se debe confiar en la prueba con `arping`. Una colisión de direcciones causa comportamiento errático en toda la red.

## 4. DHCP y búsqueda en el router

**Ventajas**: cero configuración manual, el router gestiona todo. Ideal para laboratorios o despliegues rápidos.

### 4.1 Configuración

**Archivo**: `dietpi.txt` (valores por defecto)

```ini
# DHCP habilitado
AUTO_SETUP_NET_USESTATIC=0
```

### 4.2 Localización de la IP asignada

Tras el primer arranque, se localiza la IP desde el panel del router:

* Acceder a `http://192.0.2.1` (o la IP del *gateway*).
* Iniciar sesión.
* Buscar la sección **"Dispositivos conectados"**, **"DHCP Leases"** o **"Clientes"**.
* Identificar la entrada por el hostname `DietPi`. Si hay varios dispositivos Raspberry Pi o el hostname no aparece, se apaga la Pi y se observa qué entrada desaparece de la lista.
* Anotar la IP asignada.

> **Nota — *DHCP Reservation***: la mayoría de routers permiten reservar una IP por MAC (*DHCP Reservation*). Es un punto medio ideal: la Pi sigue usando DHCP, pero siempre recibe la misma IP sin configuración manual en el dispositivo.

---

## 5. Verificación post-instalación

Tras insertar la microSD y encender la Pi, se espera **1–2 minutos**: el primer arranque de DietPi expande el filesystem y aplica la configuración.

Luego se procede según la estrategia de IP elegida.

### 5.1 Conexión con IP estática

Se conecta directamente a la IP declarada:

```bash
ssh dietpi@192.0.2.50
```

Si no responde:

* Verificar conectividad básica: `ping -c 3 192.0.2.50`.
* Si el ping falla, la Pi no arrancó o no se asoció a la red (Wi-Fi o Ethernet). Revisar [`06-troubleshooting.md`](../06-troubleshooting.md).
* Si el ping funciona pero SSH no, el problema está en el servicio SSH o en el firewall del router.

### 5.2 Conexión con DHCP

Se localiza la IP asignada desde el panel del router (ver sección anterior), o se utiliza uno de estos métodos alternativos:

```bash
# 1. mDNS (solo si hay un servicio mDNS activo en la Pi)
ping dietpi.local
ssh root@dietpi.local

# 2. Escaneo de red con nmap
nmap -sn 192.0.2.0/24

# 3. ARP scan (más rápido en redes locales)
sudo arp-scan --localnet
```

> **Nota sobre mDNS**: DietPi no incluye por defecto un servicio mDNS (por ejemplo Avahi), así que `dietpi.local` puede no resolver en la primera conexión. Si falla, se usa nmap o arp-scan.

Una vez identificada la IP:

```bash
ssh root@<IP_ASIGNADA>
```

---

## 6. Verificación del sistema (aplica a ambas estrategias)

Una vez dentro por SSH, se verifica el estado del nodo:

```bash
# Estado de servicios DietPi
dietpi-services status

# Confirmar hostname y OS
hostnamectl

# Confirmar IP y estado de las interfaces
# (wlan0 para Wi-Fi, eth0 o similar para Ethernet)
ip -br addr

# Confirmar conectividad a Internet
ping -c 3 1.1.1.1
```

**Salida esperada**: todos los comandos devuelven resultados sin errores. Si es así, el nodo está operativo y accesible remotamente.

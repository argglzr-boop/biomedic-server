# ⚙️ Instalación y Flasheo

> **Navegación**: [← Hardware](01.1-hardware.md) | [Aprovisionamiento →](01.3-provisioning.md)

Descarga de la imagen oficial de DietPi, verificación de integridad
(SHA-256) y flasheo de la microSD para el nodo biomédico.

---

## 1. 📥 Descarga de Imágenes

| Recurso | Enlace |
|---|---|
| Raspberry Pi Imager | https://www.raspberrypi.com/software/ |
| DietPi (imagen oficial) | https://dietpi.com/#downloadinfo |

> ⚠️ Al descargar desde DietPi, selecciona la variante correspondiente
> a **Raspberry Pi 2/3/4/Zero 2 (ARMv8)**.

---

## 2. 🔐 Verificación de Integridad (SHA-256)

Antes de flashear, verifica el hash de la imagen para descartar
corrupción o manipulación durante la descarga:

```bash
# El hash se obtiene del archivo de hash publicado por DietPi junto a la imagen
echo "<hash_publicado>  DietPi_RPi234-ARMv8-Trixie.img.xz" | sha256sum -c

# Salida esperada:
# DietPi_RPi234-ARMv8-Trixie.img.xz: OK
```

> ⚠️ El formato de `sha256sum` requiere **dos espacios** entre el hash
> y el nombre del archivo. Un solo espacio produce error.

Si la salida no es `OK`, la imagen está corrupta o fue manipulada:
vuelve a descargarla desde la fuente oficial.

> 💡 **Tip**: el hash se publica junto a la imagen en el sitio de
> DietPi. Cópialo directamente para evitar errores de transcripción.

## 3. 💾 Preparación y Flasheo

### 3.1 Descomprimir la imagen (solo para `dd`)

Raspberry Pi Imager acepta `.img.xz` directamente. Si vas a usar la
Opción A, puedes saltarte este paso.

```bash
unxz DietPi_RPi234-ARMv8-Trixie.img.xz
# Alternativa si no tienes `unxz`:
# xz -d DietPi_RPi234-ARMv8-Trixie.img.xz
```

Esto genera `DietPi_RPi234-ARMv8-Trixie.img` (y elimina el `.xz`
original), listo para escribir en la microSD.

### 3.2 Flashear la microSD

**Opción A — Raspberry Pi Imager** (recomendado para principiantes)

1. Abrir Raspberry Pi Imager.
2. Elegir **"Use custom"** y seleccionar la imagen descargada.
3. Seleccionar la microSD como destino.
4. Clic en **"Write"**.

**Opción B — `dd`** (línea de comandos, Linux)

```bash
# ⚠️ Identifica el dispositivo correcto antes de ejecutar
lsblk

# Desmonta las particiones que el sistema haya montado automáticamente
sudo umount /dev/sdX*

# Escribe la imagen (ajusta /dev/sdX a tu dispositivo)
sudo dd if=DietPi_RPi234-ARMv8-Trixie.img of=/dev/sdX \
    bs=4M status=progress conv=fsync
```

> 🛑 **Advertencia**: `dd` escribe sin confirmación. Si seleccionas el
> dispositivo equivocado, destruirás datos irreversiblemente.
> Verifica la salida de `lsblk` dos veces antes de ejecutar.

> 🍎 **macOS**: usa `diskutil list` para identificar el disco,
> `diskutil unmountDisk /dev/diskN` para desmontarlo, y `bs=4m` (en
> minúscula) con `/dev/rdiskN`. macOS no soporta `status=progress`;
> presiona `Ctrl+T` para ver el avance.

## 5. ✅ Verificación del Flasheo

Tras escribir la imagen, verifica que la partición `boot` esté presente
y contenga los archivos esperados:

```bash
# Linux
ls /media/$USER/boot
# (en algunas distros puede montarse en /run/media/$USER/boot)

# macOS
ls /Volumes/boot
```

```bat
:: Windows (X: es la letra asignada a la partición boot de la microSD)
dir X:\
```

Deberías ver al menos:

- `dietpi.txt`
- `dietpi-wifi.txt` (puede no existir en versiones recientes)
- `config.txt`

Si los ves, el flasheo fue exitoso. **No expulses aún la microSD** — el
siguiente paso es configurar el aprovisionamiento *headless* (sin
monitor).

# ⚙️ 01.2 — Instalación y Flasheo

> **Navegación**: [← Hardware](01.1-hardware.md) | [Aprovisionamiento →](01.3-provisioning.md)

Descarga de la imagen oficial de DietPi, verificación de integridad (SHA-256) y flasheo de la MicroSD High Endurance para el nodo biomédico.

---

## 1. Descarga de imágenes

| Recurso | Enlace |
|---|---|
| **Raspberry Pi Imager** | https://www.raspberrypi.com/software/ |
| **DietPi (imagen oficial)** | https://dietpi.com/#downloadinfo |

> Al descargar desde DietPi, se debe seleccionar la variante correspondiente a **Raspberry Pi 2/3/4/Zero 2 (ARMv8)**.

---

## 2. Verificación de integridad (SHA-256)

Antes de flashear, se verifica el hash de la imagen para descartar corrupción o manipulación durante la descarga:

```bash
# El hash se obtiene del archivo de hash publicado por DietPi junto a la imagen
echo "<hash_publicado>  DietPi_RPi234-ARMv8-Trixie.img.xz" | sha256sum -c

# Salida esperada:
# DietPi_RPi234-ARMv8-Trixie.img.xz: OK
```

> El formato de `sha256sum` requiere **dos espacios** entre el hash y el nombre del archivo. Un solo espacio produce error.

Si la salida no es `OK`, la imagen está corrupta o fue manipulada: se debe volver a descargar desde la fuente oficial.

> **Nota**: el hash se publica junto a la imagen en el sitio de DietPi. Se recomienda copiarlo directamente para evitar errores de transcripción.

---

## 3. Preparación y flasheo

### 3.1 Descomprimir la imagen (solo para `dd`)

Raspberry Pi Imager acepta `.img.xz` directamente. Si se va a usar la Opción A, este paso puede omitirse.

```bash
unxz DietPi_RPi234-ARMv8-Trixie.img.xz
# Alternativa si no se dispone de `unxz`:
# xz -d DietPi_RPi234-ARMv8-Trixie.img.xz
```

Esto genera `DietPi_RPi234-ARMv8-Trixie.img` (y elimina el `.xz` original).

### 3.2 Flashear la MicroSD 

**Opción A — Raspberry Pi Imager** (recomendado para principiantes)

* Abrir Raspberry Pi Imager.
* Elegir **"Use custom"** y seleccionar la imagen descargada.
* Seleccionar la MicroSD como destino.
* Clic en **"Write"**.

### 3.3 Flasheo en macOS

**Opción B — `dd`** (línea de comandos, Linux)

```bash
# Identificar el dispositivo correcto antes de ejecutar
lsblk

# Desmontar las particiones que el sistema haya montado automáticamente
sudo umount /dev/sdX*

# Escribir la imagen (ajustar /dev/sdX al dispositivo)
sudo dd if=DietPi_RPi234-ARMv8-Trixie.img of=/dev/sdX \
    bs=4M status=progress conv=fsync
```

> **Advertencia**: `dd` escribe sin confirmación. Si se selecciona el dispositivo equivocado, se destruirán datos irreversiblemente. Verificar la salida de `lsblk` dos veces antes de ejecutar.

> **macOS**: usar `diskutil list` para identificar el disco, `diskutil unmountDisk /dev/diskN` para desmontarlo, y `bs=4m` (en minúscula) con `/dev/rdiskN`. macOS no soporta `status=progress`; se debe presionar `Ctrl+T` para ver el avance.

## 4. Resiliencia

El sistema se instala con el filesystem por defecto de DietPi (ext4 con `noatime` en la partición de datos). La estrategia de respaldo y recuperación (IaC vía repositorio Git para configuraciones y servicios, dumps lógicos transaccionales de la base de datos, Golden Image para el aprovisionamiento base y sincronización remota del dump por `rsync` sobre WireGuard) está documentada en [`resilience-strategy.md`](../00-resilience/003-resilience-strategy.md).

## 5. Verificación del flasheo

Tras escribir la imagen, se verifica que la partición `boot` esté presente y contenga los archivos esperados:

```bash
# Linux
ls /media/$USER/boot
# (en algunas distros puede montarse en /run/media/$USER/boot)

# macOS
ls /Volumes/boot
```

```bat
:: Windows (X: es la letra asignada a la partición boot de la MicroSD)
dir X:\
```

Se debería ver al menos:

* `dietpi.txt`
* `dietpi-wifi.txt` (puede no existir en versiones recientes)
* `config.txt`

Si aparecen, el flasheo fue exitoso. **No expulsar aún la MicroSD **: el siguiente paso es configurar el aprovisionamiento *headless* (sin monitor).

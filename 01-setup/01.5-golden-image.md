# 💾 Golden Image (Pre-Ansible) y Stock de Contingencia

> **Navegación**: [← network](01.4-network.md) | [Bootstrap Ansible →](01.6-bootstrap-ansible.md)

Este documento define el procedimiento para crear la **Golden Image** (imagen base reproducible) de la MicroSD. Esta imagen captura el estado del nodo justo después de validar la conectividad SSH, pero **antes** de aplicar la configuración de Ansible (LUKS, Btrfs, Hardening, etc.).

El objetivo es doble:
1. **Acelerar despliegues:** Servir como punto de partida idempotente para futuros nodos.
2. **Stock de contingencia:** Tener réplicas listas para sustituir una MicroSD en caso de fallo físico (RTO reducido).

---

## 1. ¿Cuándo se crea la Golden Image?

La imagen **debe** crearse una vez que se han cumplido estrictamente los siguientes puntos:

1. La Raspberry Pi ha completado su primer arranque (la partición raíz se ha expandido).
2. El nodo responde a `ping` en su IP asignada (ver `network.md`).
3. La conexión SSH funciona mediante llave pública (`Ed25519`).
4. Se ha verificado que el servidor SSH es OpenSSH y no Dropbear.
5. El sistema no presenta errores en `systemctl --failed`.

> ⚠️ **Regla de oro:** La Golden Image se clona con el sistema operativo funcional, **NUNCA** con Ansible ejecutándose o configurado como un servicio en segundo plano.

---

## 2. Contenido de la Golden Image

Es fundamental entender qué se clona y qué se genera de forma única para cada nodo para no comprometer la seguridad.

| Componente | ¿Incluido en la Imagen? | Notas |
| :--- | :--- | :--- |
| Sistema DietPi base | ✅ **Sí** | Con las optimizaciones de RAMlog aplicadas. |
| Red (`dietpi.txt` / `dietpi-wifi.txt`) | ✅ **Sí** | Configuración de IP y Wi-Fi ya aplicada. |
| Servidor OpenSSH | ✅ **Sí** | Habilitado y funcionando. |
| Llave pública SSH (`id_ed25519.pub`) | ✅ **Sí** | En `/root/.ssh/authorized_keys` y `/home/dietpi/.ssh/authorized_keys`. |
| Partición LUKS / Btrfs | ❌ **No** | Se crea vía Ansible (`03_storage_luks`). |
| Configuración WireGuard / auditd | ❌ **No** | Se aplica vía Ansible (`02_hardening`). |
| Llaves privadas SSH | ❌ **No** | Residen solo en el Control Node (Bitwarden). |
| Datos clínicos (telemetría) | ❌ **No** | El nodo aún no entra en producción. |

## 3. Procedimiento de Clonación (en macOS)

Para realizar la copia de seguridad, la Raspberry Pi debe estar apagada de forma segura y la MicroSD debe estar insertada en el dispositivo de gestión.

### 3.1 Identificar el disco de la MicroSD en macOS
Identificación de la SD en terminal:
```bash
diskutil list
```
Se debe buscar el disco que corresponda a la MicroSD (por ejemplo, `disk4`). **No se debe confundir con las particiones** (`disk4s1`, `disk4s2`) y deberá emplearse el identificador del disco completo (ej. `/dev/rdisk4`).

### 3.2 Desmontar disco identificado
```bash
diskutil unmountDisk /dev/disk4
```

### 3.3 Crear la imagen de disco
Se emplea `dd` para extraer la imagen cruda de la tarjeta. Sustituir `disk4` por el número correcto:
```bash
sudo dd if=/dev/rdisk4 of=~/biomedic-golden-preplaybook.img bs=4m
```

### 3.4 Comprimir y verificar la integridad
La imagen en crudo pesará lo mismo que la tarjeta (ej. 16 GB), pero se comprimirá drásticamente porque la mayor parte está vacía. La herramienta zstd ofrece una relación compresión/velocidad superior a gzip y más rápida que xz, con menor consumo de memoria que este último. El archivo resultante es biomedic-golden-preplaybook.img.zst.
```bash
# Comprimir
zstd -19 -T0 -k ~/biomedic-golden-preplaybook.img

# Generar checksum (para asegurar que no se corrompa en el almacenamiento)
shasum -a 256 ~/biomedic-golden-preplaybook.img.zst > ~/biomedic-golden-preplaybook.sha256
```

### 3.5 Almacenar en el repositorio de contingencia
Guardar los archivos generados en un almacenamiento seguro o NAS, etiquetados con la versión:
```
/golden-images/
└── v1.0.0/
    ├── biomedic-golden-preplaybook.img.gz
    └── biomedic-golden-preplaybook.sha256
```

## 4. Restauración en Caso de Contingencia

Si la MicroSD de un nodo en producción falla (según el escenario B de `resilience-strategy.md`), el procedimiento es el siguiente:

1. Insertar una MicroSD nueva o de stock.
2. Descomprimir y grabar la Golden Image:
   ```bash
   gunzip -c biomedic-golden-preplaybook.img.gz | sudo dd of=/dev/rdiskX bs=4m
   ```
3. Insertar la SD en la Raspberry Pi y encender.
4. El nodo arrancará, se conectará a la red y tendrá SSH listo.
5. Ejecutar los playbooks de Ansible desde el Control Node (`bootstrap-ansible.md`).
6. Restaurar los datos clínicos desde el respaldo remoto (Btrfs send/receive).

---

## 5. Advertencia: SSH Host Keys Compartidas

Al clonar la misma imagen en múltiples tarjetas SD, **todas compartirán las mismas claves de host SSH** (`/etc/ssh/ssh_host_*`). Esto genera un riesgo de suplantación de identidad y conflictos en `known_hosts`.

Para despliegues futuros con múltiples nodos, se deberá planificar la inclusión de una tarea automatizada (por ejemplo, mediante un Playbook de Ansible) que regenere estas llaves únicas en el primer arranque de cada nodo clonado, garantizando así la identidad criptográfica individual de cada dispositivo.
